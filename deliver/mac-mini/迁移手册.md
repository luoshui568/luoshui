## 一、先弄清一件事：这个系统有三块，搬家方式完全不同

| 资产 | 在哪 | 怎么搬 | 规模 |
|---|---|---|---|
| **构建脚本 + 模板 + 交付页 + seed** | GitHub `luoshui568/luoshui` | `git clone` 自动拿到 | 214 个文件 / 3.88 MB |
| **工具脚本（`_*.py`）+ 记忆 + 技能** | 只在 Windows 本机 | 迁移包 `luoshui-workspace.tar.gz` | 373 个条目 / 2.5 MB |
| **API 密钥 / token** | `~/.workbuddy/mcp.json` 等 | 迁移包 `luoshui-secrets.tar.gz`（单独传） | 3 个文件 |
| **CloudBase 管理凭据** | WorkBuddy 登录态里 | **搬不了，Mac 上重新授权一次** | — |

⚠️ **最容易踩的坑**：以为「代码在 GitHub 上就万事大吉」。实际上 `.gitignore` 第 31 行 `build/_*` 把 **225 个脚本**全挡在仓库外了，里面包括：

- `_mk_*.py` —— 各公司的建库脚本，**是权威数据源**（seed 只是它的产物）
- `_score_*.py` —— 槽 29 自动评分与落库
- `_do_upload.py` / `_mcp_upload.py` —— 上线通道
- `_fill_deep.py`（108 KB）、`_goldify.py` —— 补深度与模块搬家
- `_mk_lib.py` —— `dump()` / `pe_series()` 公共库

**没有这些，Mac 上只能看不能改。**

☐ Xcode 命令行工具装好

默认装到 `~/WorkBuddy/luoshui`。想换位置：


### 第 3 步 · 改路径（关键）

脚本里 301 处硬编码了 `C:\Users\50522\...`，必须改写：

```bash
python3 ~/WorkBuddy/luoshui/build/_port_paths.py           # 先干跑，只报告
python3 ~/WorkBuddy/luoshui/build/_port_paths.py --go      # 确认无误再实际改
```

- 每个文件改前备份成 `*.winbak`
- 改完自动做两件事：**再扫一遍确认 0 处残留** + **全部 `.py` 语法体检**

改写规则（工具自动识别，不需要你填）：

| 原样 | 改成 |
|---|---|

☐ 干跑输出确认无误
☐ `--go` 改写完成，自检显示「残留 0 处」+「语法全部通过」

### 第 4 步 · WorkBuddy 侧（必须手动）

☐ 装 **WorkBuddy macOS 版**，登录同一账号 —— 云记忆、专家、内置能力跟账号走，登录即回

☐ 关掉再开一次 WorkBuddy（让 `~/.workbuddy/mcp.json` 生效）


## 三、Mac 上继续干活：日常流程没变

**改一个页面并上线**（四步，和 Windows 完全一样）：

```bash
python3 build/grab_live_backup.py                    # 1. 先抓线上备份
python3 build/_do_upload.py --files "deliver/xxx.html:/xxx.html"   # 2. 上传
python3 build/live_check_v4.py                       # 3. 四页核对
```

**新建一份研报**：

```
_mk_<code>.py  →  data_v31_<code>.json  →  report_build_v31.py <code>
              →  report_<code>.json     →  push_reports_v31.py
```

**只补某一槽**：绝不重跑 `build()`（会降级），用 `_fill_deep.py` 原位写回。

**同步到 GitHub**：

```bash
git add -A && git commit && git push
```

Mac 上 git 是系统自带的，不用再折腾 PortableGit 那套。

## 四、Windows → macOS 对照表

| 事项 | Windows | macOS |
|---|---|---|
| git | `~/.workbuddy/binaries/PortableGit/.../git.exe`（不在 PATH，要手加） | 系统自带（Xcode CLT），直接可用 |
| Python | `C:\Users\50522\.workbuddy\binaries\python\versions\3.13.12\python.exe` | `python3` |
| 无头浏览器 | `msedge.exe` | `Google Chrome`（参数 `--headless=new` 通用） |
| PATH 玄学 | 常常 `command not found`，要手动 export 修复 | 不存在这个问题 |
| 命令冲突 | ⚠️ `timeout` / `sort` / `find` / `bash` 会命中 Windows 同名程序，报莫名错误 | 不存在 |
| 行尾 | 产物多为 CRLF | git 可能提示 `LF will be replaced`，可忽略 |
| 权限 | 无 | 首次跑脚本可能要 `chmod +x`；系统目录写入需授权 |

**关于行尾**：这次改写工具用的是**字节级二进制读写**，只换路径不动行尾，所以 CRLF 文件原样保留，不会出现「改了 3 处、diff 显示 40 万行」的假差异。

## 六、两个已知遗留问题（建议顺手处理）

### ① 225 个工具脚本仍在 git 之外

这是**真正的风险**：Mac 上要是没拿到迁移包，或者以后换了第三台机器，`_mk_*.py` 这些权威数据源就断了。

建议把核心工具加进版本控制（在 `.gitignore` 的 `build/_*` 之后加例外）：

```gitignore
!build/_mk_*.py
!build/_mk_lib.py
!build/_score_*.py
!build/_fill_deep.py
!build/_goldify.py
!build/_do_upload.py
!build/_mcp_upload.py
!build/_norm_bold.py
!build/_port_paths.py
!build/_mac_pack.py
```

要我做这件事的话说一声，我会先审一遍这批文件里有没有夹带路径/口令，再提交。

### ② `.workbuddy/memory/` 也没入库

项目记忆（含 `MEMORY.md`、`MEMORY_ARCHIVE.md` 和全部日志）同样被 `.gitignore` 的 `.workbuddy/` 规则排除。这次靠迁移包带了，但长期看应该入库——记忆才是这个项目的「操作系统」。

## 七、出问题怎么办

| 症状 | 原因 | 处理 |
|---|---|---|
| `_port_paths.py --go` 后脚本报错 | 个别路径形态没覆盖到 | 跑 `--rollback` 还原，把报错文件发我 |
| 上传脚本报 `auth REQUIRED` | CloudBase 未授权 | 重新走设备授权（600 秒内点确认） |
| `live_check_v4.py` 报特征串缺失 | 线上页面与本地不一致 | 先 `grab_live_backup.py` 抓下来比对 |
| 无头截图全黑/8KB | Chrome 没装或路径不对 | 装 Chrome；或改 `_port_paths.py` 里的 `CHROME` 再跑一次 |
| git push 要 token | Mac 上没存凭据 | 用 SSH key，或 `brew install gh && gh auth login` |

回滚一切：

```bash
python3 ~/WorkBuddy/luoshui/build/_port_paths.py --rollback
```
