### 1.1 m2 公司历史沿革 —— 时间轴写死在 HTML 里

**现状**（`build/seed/report_600456.json` 的 m2 模块）：

```html
<div class="hist">
  <div class="h-head">
    <div class="h-en">COMPANY&nbsp;HISTORY</div>
    <div class="h-title">公司发展历程</div>
    <div class="h-sub">二十余载 · 从代号902到中国钛工业第一股</div>
  </div>
  <div class="h-track">
    <div class="h-line"></div>
    <div class="h-nodes">
      <div class="h-node"><div class="h-dot"></div>
        <div class="h-card"><div class="h-year">1999</div><div class="h-txt">…</div></div>
      </div>
      … 共 7 个 h-node（1999 / 2002 / 2006 / 2007 / 2008 / 2021 / 2026）
    </div>
  </div>
  <div class="h-foot">1999 — 2026 · 钛业报国 · 迈向航空航天新周期</div>
```

**问题**：
- 7 个节点、年份、正文、交错方向（odd 在上 / even 在下）**全部是字面量**，没有任何数据源。
- 底部 `.h-foot` 的「1999 — 2026」起止年份也是手写的，与新公司的实际年份区间无关。
- 副标题「二十余载 · 从代号902到中国钛工业第一股」是宝钛专属文案。
- **换一家公司，这段必须人工重写**，且节点数一旦不是 7，CSS 的 `:nth-child(odd/even)` 交错逻辑虽仍成立，但 `.h-track{height:345px}` 是硬编码高度，节点变多会被压扁。

**影响**：批量生产时无法自动填充 → 每家公司都要手写一遍 → 不可批量。

### 1.2 m3 股权结构树 —— 内联 SVG + 250 个绝对坐标

**现状**：两个函数已改为优先消费 `d['timeline']` / `d['equity_tree']`，经 `TimelineKit.selfcheck()` / `OrgTreeKit.selfcheck()` 闸门后渲染成真正的视觉件；数据缺失时才回落到表格。所以**换公司只要填 JSON，就能出与 600456 一致的时间轴和股权树**。

### 3.2 `.h-track` 高度硬编码 —— **已修复 ✅**

~~`report_theme.css` 第 19412 行：`.hist .h-track{position:relative;height:345px;}`~~

`TimelineKit.html()` 现在会按节点数算出高度并写成**行内 style**（`style="height:...px;"`）。行内写法是必需的 —— `sanitizeHtml` 会剥掉模块内的 `<style>`，只有行内样式能存活。

- 7 节点 → `345px`（与 600456 现值**逐像素相同**）
- 其他节点数 → `int(max(260, min(560, round(345 * (7/n) ** 0.55))))`
- 卡片宽同理：≤7 节点 `146px`，更多则 `max(118, int(146 * (7/n) ** 0.35))`
- 子树 `.h-card` 宽度也已行内化，不再只靠 CSS

### 3.3 树状图无响应式回退

`.sh3-tree svg{display:block;width:100%;height:auto;}` —— 靠 viewBox 等比缩放。1000×550 的比例在手机上会变得极小（8 家子公司的竖排字几乎不可读）。时间轴有 `@media(max-width:860px)` 的纵向降级，**树状图没有**（此项仍未处理，列为 P1）。

### 3.4 `_todo_96.json` 的 96 家池子

批量管线的目标名单在 `seed/_todo_96.json`。若要做全市场批量，需要确认这个池子的更新机制（当前是静态文件）。

### 6.4 改造中修掉的两个真 bug（值得记）

**① 转弯那条边上的比例徽标整个丢失。**
原逻辑把比例徽标画在 `if i < nc-2` 分支里，而「倒数第二层 → 最后一层」走的是**水平箭头**（另一条 `else` 分支），于是 `93.36%` 从未被绘制。自检断言最初也没覆盖到它 —— 后来把 `nc>=3` 时的药丸计入 rect 总数才暴露。

**② 「流入自己的比例」与「自己持有上市公司的比例」被混为一谈。**
600456 的股权链共有 **3 个比例**，语义各不相同：

| 值 | 含义 | 挂在哪条边 |
|---|---|---|
| `chain[0].pct` | 顶层实控人，**无上游**，写 `—` | 无 |
| `chain[i].pct` (i≥1) | **上一节点持有 chain[i] 的比例**（流入比例） | 该节点的入边 |
| `subject_pct` | **链末节点持有「上市公司主体」的比例** | 链末 → 上市公司的竖边 |

`chain[-1].pct` 是 93.36%（宝钛集团**自己被**陕西有色持有 93.36%），而 `subject_pct` 才是 49.40%（宝钛集团**持有**宝鸡钛业 49.40%）。二者极易互换，`selfcheck()` 里已加专门断言守护。

**③ 抽取时不能按文档顺序配对。** 比例徽标在 SVG 里的**文档顺序与链节点顺序并不对齐**，必须按几何位置（先 `y` 再文档序）排序归属 —— 否则会把 100% 和 93.36% 挂反。`_extract_flow_600456.py` 的代码注释记录了这个坑。

### 6.6 一个设计上的取舍：渲染与自检**必须分离**

最初 `TimelineKit.html()` 内部调用了 `selfcheck()`，而 `selfcheck()` 为了取证又调回 `html()` ⇒ `RecursionError`。
最终设计：**`html()` / `svg()` 只负责渲染，绝不调用自检**；`selfcheck()` 内部调用渲染以取得证据；另提供 `build()` = 自检 + 渲染，作为推荐入口。两边的 docstring 都写明了这一约定。
