# 研报模块 3「股东结构」· 全站统一标准（2026-10-14 定稿）

> **一句话规则**：所有研报（含以后新生产的）的模块 3 一律由
> `build/mkmod3_std.py` 按 `build/seed/m3std/m3_<code>.json` 生成，
> 版式以**宝钛股份 600456** 为冻结范例。**不要手写这个模块的 HTML，也不要另起版式。**

## 1. 为什么有这份标准

用户 2026-10-14 明确要求：「研报的股东结构要求与宝钛股份的股东结构样式一致，以后生产的所有研报
都要一致，这块不可随意制作」。此前各研报各写各的 —— 盛和资源等 10 篇用的是自造
「项目 / 数值 / 说明」小表，没有环形占比、没有关键指标、没有股权结构图；宝钛是唯一做全的。

因此把宝钛那版**冻结成模板**，并把「版式」与「数据」彻底分开：

```
规格 JSON（只装数据）  →  mkmod3_std.py（只管版式）  →  模块 3 HTML
```

**铁证**：`python3 mkmod3_std.py 600456 --check` 的产出与线上 600456 的模块 3
**逐字节一致**（md5 `45c004bd…`，19374 字符）。也就是说生成器产出的就是「宝钛样式」本身。

## 2. 骨架（顺序与类名都不可改）

| # | 元素 | 类名 / 标签 | 说明 |

## 3. 怎么用

```bash
cd build
python3 mkmod3_std.py --list                 # 列出现有规格 + 与 seed 现状是否一致
python3 mkmod3_std.py 600392 --check         # 生成并与 seed 比对（不写盘）
python3 mkmod3_std.py 600392 --dump /tmp/x.html
python3 mkmod3_std.py 600392 --write         # 备份后写进 seed/report_600392.json
python3 mkmod3_std.py 600392 --push          # 与线上比对（dry-run）
python3 mkmod3_std.py 600392 --push --go     # 只 PATCH <code>_m3 一行：备份 → 写库 → 回读核对
python3 _m3std_preview.py 600456 600392 --out /tmp/m3prev   # 目视预览页
python3 _m3std_shot.py /tmp/m3prev /tmp/shots/x.png 3400     # 起本地 http + Edge headless 截图
```

**新研报的流程**：复制一份最接近的规格 → 改数据 → `--check` 目视 → `--dump` 截图确认 → `--write`
→（报告入库时随 `push_reports_v31.py` 一起上）/ `--push --go` 单模块补写。

## 4. 规格 JSON 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `code` / `name` / `exch` | ✅ | 600392 / 盛和资源 / SH |
| `logo` | — | `true` 且存在 `seed/m3std/logo_<code>.b64` 时把 logo 内联进环心；缺省则环心只放名称+代码 |
| `donut.buckets[2]` | ✅ | `{label, pct}`，两筐合计须 100；`grad` 可换渐变；`lx`/`ly` 可锁死标签位置 |
| `legend[2]` | ✅ | `{color, hd, big, unit, sub}` |
| `stats[4]` | ✅ | `{k, v, u, gold}`；顺序：总市值 → 国企外流通市值 → **控股股东持股（gold）** → 前十大合计 |
| `read[]` | ✅ | 解读要点（HTML 片段，可含 `<strong>`） |
| `top10.head/rows/sum` | ✅ | `head` 缺省＝宝钛表头；`sum` 里 `—` 不加粗 |
| `tree.chain[]` | ✅ | 主链（不含上市公司本身），`pct` 写**上一级持股比例**；无持股关系（行政隶属）就留空 |
| `tree.bar` | ✅ | 上市公司主条 `{label, pct}` |
| `tree.children[]` | ✅ | 主条下方子公司一排 `{label, pct}`，**固定 6–8 个**（不足 6 个说明取数没做全）。`pct` 写成字符串（`"51%"`）；**未披露时写 `null` / 省略** → 渲染成虚线、不画药丸；`label` **≤13 字**（超了竖排会溢出 212px 框，长名请缩写并在 `cap` 里给全称） |
| `tree.cap` / `tree.aria` | ✅ / — | 图注（写清链条含义）/ 无障碍描述 |
| `src` | ✅ | 来源 + 口径说明 |

## 5. 内容纪律（比样式更重要）

1. **不换算已披露的数字**。原始披露是「2.4638 亿 / 9,627.1094 万」就照录，表头随之写成
   「持股数量（股）」；为凑统一表头去换算会破坏合计自洽。
2. **缺项不编造**。子公司持股比例只在 F10／年报**确有披露**时才写数字；查不到就 `pct: null`
   →渲染成**虚线、不画药丸、不出现任何数字**（图注里用一句话说明「XX 持股比例未披露，图留空」）。
   绝不估算、绝不按注册资本倒推。链条里若两级之间是行政隶属而非持股，同样**不标百分比**。
   **取数顺序**：同花顺 F10 `basic.10jqka.com.cn/<code>/company.html`「参股控股公司」（首选，带参控比例）
   → 大智慧 `webf10.gw.com.cn/SH|SZ/B15/...`「参控公司」→ iFinD MCP `get_stock_shareholders`。
   **选谁进图**：按投资金额 / 是否并表排序取前 6–8 个主要子公司。
3. **环形两筐的来源**：国企＝前十大股东里「国家 + 国有法人」合计（取整）。市值图例 = 总市值 × 占比；
   国企外流通市值 = 总市值 ×（1 − 国企占比）—— 这是**口径换算值**，必须写进 `src`。
4. **标签落位**：默认按扇形角平分线自动落位（半径 70）；宝钛因近似五五分用了对称硬编码
   `lx=190/ly=112`、`lx=50/ly=112`，属冻结参数勿改。小占比（如 17%）**必须**用自动落位，
   否则标签会跑到另一段弧上。
5. 解读里至少覆盖：控股/无控股判断、国资或民企属性对公司的实际意义、股东户数（蓝图 `must` 项之一，
   没有专版块就放进要点）、限售解禁核实结论。
